# R7 人工文字修补验证报告

基于R6 `67c7c2e0c3b39ddced4ab71144cd2c5150488aab` 增量。实施计划及数据约定见 STANDALONE_TEXT_REVISIONS_PLAN.md；使用、接口和迁移见 STANDALONE_TEXT_REVISIONS.md。现有测评分支保留所有历史成果。本轮只更新独立HTTP开发服务，没有生产变更、OCR或云端调用。

## 实现

独立TextRevisions模块校验已登记稿、稳定位置、资源哈希和完整映射。新稿完整复制未改位置、替换当前页，原子登记；空串删除、无变化不重复、请求幂等、链头冲突409。结构JSON、逐页文字及安全阅读视图同步更新。修订日志保留前后全文、父稿和原件SHA，编辑字不沿用旧坐标冒充精确位置。反馈及原图质量保持独立。

右侧增加编辑/阅读、保存、保存后排版、差异、历史恢复和准确父文字稿入口。历史稿只读；新版本自动选中，左侧位置保留。切页/切文件/返回项目前明确保存、放弃或取消；浏览器刷新/关闭使用原生离开保护。保存和排版状态分别显示，排版失败仍保留修订。离线明确只读，不显示假保存。

实际浏览器排查修复了页码回车重复触发、回车默认动作误激活提示按钮、同页失焦重复导航退出编辑、异步刷新覆盖保存/排版状态的问题。排版完成回调仅追加新产物选项，不重建当前编辑框；专项验证不会丢失用户后来输入的草稿。早期测试及合成项目全部保留在忽略目录，没有重置历史。取消浏览器reload本来会终止导航，测试改为检查真实beforeunload对话框，不把取消导航的等待超时当作服务故障。

## 独立实测

Chromium140.0.7339.16，桌面1440×1000，另有390×844离线窄屏检查。独立2CPU/4GiB开发环境，沿用60秒生成限时、上传512MiB/PDF1000页/选择1000页配置。

合成24页PDF和来源22/23/24的完整文字稿：当前23页将“错宇”改为“错字”，刷新仍保留；22/24页逐字保持，原稿仍是“错宇”。JSON正文、阅读视图和Markdown一致。模板沿用questions-zh-cn/1.0.0，不改公共版本。真实DOCX和PDF均含修改，排版1.427398秒，脚本峰值81424KiB；不是整册性能。Word经实际LibreOffice渲染，PDF从实际PDF渲染；本例两张页面PNG相同。开发侧看过两份完整单页及编辑、差异、冲突截图，中文、标题、选项和文档页码可见，没有发现裁切或空白页。

真实双标签从同一基础版本提交，第二标签409并保留草稿；连续保存及恢复旧内容均追加新版本。左侧24页与右侧来源23页保持独立，保存没有强行同步来源。演示项目仅有format-artifact任务，识别任务0、云端请求0。修订操作标记developer-agent，不冒充用户确认。

本轮开始时21个旧项目的任务记录完全保持，216个旧登记文件SHA逐项不变。没有改原件、原始OCR、业务正文或历史结果。相关R6按需预览、原图质量/评论、管理、模板与文档回归通过。

## 离线交付与限制
