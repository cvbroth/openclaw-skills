# R6 原件分页与工作台

## 使用与边界

在原件已登记且基本有效性检查取得PDF总页数后，原件拥有完整物理页索引，不需要先提取、OCR或评价。评审两侧均可选原件；输入页码并回车或使用上下页。原件显示物理页／总页数，排版稿显示自身输出页；双方位置、缩放、滚动独立。原图质量为空不阻止浏览。原图评论绑定真实physical_page定位，未缓存页同样可评论。

详情采用上下全宽布局：原件信息、任务、内容与产物。产物主操作为查看／对照；更多菜单包含改名、回收、技术信息和预览维护。显示名、路径、哈希、缓存与评论身份仍分离。没有可用文字稿时提示并禁用排版；模板使用已发布配置的友好名称及版本。任务与产物日期统一为zh-CN显示。轮询不重新创建表单或收起展开项。

## 实现与接口

`POST /api/projects/:project_id/source-preview/:physical_page`，JSON可带`{"retry":true}`。仅登记的项目内本地PDF，页码严格限制到已知总页数。返回SUCCEEDED、FAILED或BUSY；包含实际错误、缓存命中、图片相对路径与哈希及渲染参数。外部引用不扩大为任意宿主文件访问。原件缺失或哈希变化明确失败，不更新登记哈希、原件或历史评论。

缓存键为原件SHA、物理页、source-page-v1及固定渲染参数的SHA。当前PyMuPDF1.25.5、120dpi、无alpha、PNG、每页最多2000万像素。该预览尺寸不代表OCR输入尺寸，既有模型输入及其记录不变。缓存图片校验哈希；丢失/损坏可重新生成，版本变化使用新缓存。原已识别图片/旧定位保留legacy记录，不覆盖原始识别文件或评价。

原件单页预览复用preview_worker，独立单并发信号量，不进入转换队列，也不共享转换任务的取消状态。子进程30秒上限、最小环境、不传递引擎凭据；线程环境限制1。开发容器总2CPU/4GiB、无额外swap、只读根保持，预览和识别竞争同一额度，并非额外申请资源。BUSY前端最多100次350ms等待，用户切页后旧等待失效。没有保证任意重PDF或高负载下的固定响应时间；超时明确报错重试。导出拒绝本项目正在渲染的状态，避免打包半写图片。

前端独立递增请求令牌校验产物与物理页，晚到响应不得替换当前页。越界保留当前预览并提示，不回退到第一页。没有可靠来源关系时不自动推测输出页对应原页。渲染器、ID、完整协议与缓存资料收入技术详情。

## 旧项目与离线

旧本地PDF根据已登记路径及基本元数据补齐索引；总页数缺失时只打开文件取得总数，不渲染、不识别、不扫描目录。迁移保持project_id、artifact_id、原件SHA及revision，原有页视图/定位留legacy，原始识别与评论历史不改写。只在项目首次读取/保存时增量补齐，不批量搬文件。

在线项目JS读取最新索引，完整页码均可选。离线同样保留完整索引，但页目录明确区分已缓存／未缓存；只有已缓存图片可以展示。未缓存显示无法离线生成，需要在线按需打开后重新导出。原文件有下载入口不等于该页已经在评审中预览成功。外部引用未打包或不可访问时明确提示；没有自行复制外部原件。

回退前等待开发任务终态，保留新预览/评论及原项目备份，恢复旧代码即可；旧UI可能只识别已有图片，无法提供本轮完整浏览。不要用旧整库覆盖新评论。生产FileTools、OpenClaw、Skill、模板和限额均未改动。
