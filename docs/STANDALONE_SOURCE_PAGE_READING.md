# 第二阶段：按登记来源页连续阅读

本轮执行基线为远端最新d8b9162498f858444955281099abf2d33fd6263e，保留第一阶段工作台布局。仅完善原件页与文字对应阅读，不开发段落点击跳转、模型疑点标亮，不重新识别、不调用付费模型。

## 已实现

右侧文件/文字位置导航旁新增紧凑“来源页”输入与“到左页”，面板关闭仍可输入；窄屏通过已有“左右切换”查看右侧导航。输入原件物理页后，按当前文字版本登记顺序连续显示全部匹配片段，不逐个要求选择候选。原件页数和文字片段数量互不替代。

片段标题显示原始文字位置与登记来源物理页。跨页片段显示全部来源页并明确说明完整显示、未精确拆分；印刷页码只在原件元数据明确提供`printed_page`时显示，否则为“未登记”。导出文档输出页仍独立命名，不冒充原件页。版本还有未知来源片段时提示其数量，不承诺该页内容完整覆盖。

来源页阅读临时忽略右侧错误/评论筛选，提示当前策略，避免内容被静默隐藏；质量筛选只筛选左侧原件。返回普通文字位置导航后恢复筛选。没有登记匹配、缺少映射和文字资源读取失败均明确显示；无匹配时清空上一页正文。左右不强制联动，“到左页”只改变右侧。

聚合阅读中先选具体片段，再从顶部编辑；提交仍使用原片段的稳定locator和当前版本哈希。保存只改该片段，其他片段及来源关系不变，不需要手动维护分隔标记。修订API、结构及变更记录补充保留`source_pages`。评论仍以版本ID/哈希/稳定locator绑定，不以聚合后的第几个卡片绑定；未选片段时禁用文字评论，可选原图评论。

历史版本只读，选中具体片段后可恢复为新版本再编辑；保留取消、失败草稿、切换保护和明确版本模板导出。缺少来源页但稳定片段和文字资源完整的版本继续独立编辑。只有一个`document`位置、整稿与文字资源及哈希一致的旧稿，可明确编辑整份文字，仍不虚构来源页或分段。

## 已有数据核实（部署前）

38个项目、73个文字版本：57个全部片段有来源字段，16个没有来源字段，23个人工修订版本。盘点不是重新OCR，也没有改写数据。16个无映射版本包含11个模板预览、4个历史合成/开发演示、1个真实习题册早期整稿；项目名、版本ID和缺失情况放私有交付清单。真实早期整稿的单一document文字资源与整稿、哈希一致，已提供整份文字编辑降级。

| 数据 | 已登记含义与边界 |
|---|---|
| 项目`source_artifact_id`、原件SHA256、物理索引 | 明确原件及其物理页总数；不是文字片段总数 |
| 文字artifact、`pages[]`、资源SHA256 | 数组为整稿登记组装顺序；各资源为独立片段正文，不按题号/序号反推来源 |
| 片段`source_page` | 明确的单一来源物理页 |
| 片段`source_pages` | 多个来源页；整体覆盖关系，不包含每页文字切分或坐标 |
| 片段`locator.kind=physical_page` | 明确物理页证据；普通block/document/output_page及歧义legacy source_page不反推物理页 |
| 人工修订 | 深复制片段视图与稳定locator、来源关系，追加新版本；修改后无精确文字坐标 |

来源字段必须为正整数；存在多个来源字段时一致性不足则不使用。版本里无映射的片段不能判断属于哪一原件页，也不猜补齐。

## 坐标盘点与可复用程度

实际引擎结果中有90个RapidOCR图像像素多边形框、94个PDF点坐标矩形框；结果输入记录保留图像宽高/SHA256，PDF结果有物理页、原件SHA256和PDF点尺寸。诊断副本和生成结构重复记录同一证据，不能把递归扫描字段数量视为独立框数量。

- RapidOCR框可在核对提交图像哈希和尺寸后复用到同一输入图像；没有完整旋转/裁剪变换，不能直接套到不同预览图。
- PDF原生框可关联明确物理页及PDF点尺寸；原生顺序不保证逻辑阅读顺序，也不能假定修订文字仍与框逐字一致。
- 远端整页转写/部分历史结构没有文字框，人工修订结构明确`coordinates: null`。
- 当前项目根的坐标证据未找到完整旋转/裁剪变换；独立旧评审工具的bbox/crop格式不等于已绑定到当前项目。不能把这些条件缺失的坐标用于精确定位。本轮仅盘点，未增加坐标交互。

## 实际验证与证据

合成项目：30页原件、6个登记片段，来源22页1片段、23页3片段，其中1片段覆盖23/24；25页失败空正文，26页无记录，另1片段无来源。第23页的登记文字位置是2、3、4，不是第23个文字片段。

- 顺序为FIRST_P23 → SECOND_P23 → CROSS_23_24；24页仅显示完整跨页片段；26页清空旧正文；失败页显示错误状态；单个文字资源读取失败保留邻段并明确报错。
- 错误/评论/原图质量筛选同时开启后，第23页仍显示3个匹配片段，并显示忽略筛选提示；普通文字位置继续按筛选工作。
- 选中文字位置3，修改为EDIT_ONLY_SECOND_P23后，其他5个片段逐项比较完全一致，稳定locator、单页和跨页映射保持。历史版本显示旧文字，恢复后全部片段与历史相同。
- 评论回执核对其原版本ID及稳定locator；未因卡片显示顺序改绑。
- 保存503失败保持草稿；切换来源页、文字位置、文件时取消切换保留草稿；原有保存/放弃/取消机制保留。
- 无映射稳定片段可独立编辑；已核实整份旧稿可独立保存，但仍没有来源页。导出默认带入明确当前修订/恢复版本。
- 1920×1080、1366×768、1024×768、768×900、390×844、320×640验证来源输入无需面板、页面无横向溢出、面板不遮盖正文。默认桌面布局仍以正文80%以上应用高度为目标。
- 真实169页习题册仅阅读物理23页并核对登记文字；截图等待原图和文字加载完成后采集，放私有包。公开[截图和逐片段测试结果](evidence/source-page-reading-20261011/)全部使用合成内容。
- 新版离线项目包含source-reader.js，可按页聚合阅读、评论JSON，服务器写入/导出仍禁用。已下载旧包不会被远程改动，重新下载即可更新。

复现：隔离fixture-only服务运行`create_source_reading_fixture.py ROOT CONFIG MANIFEST`，再运行`check_source_reading_browser.py BASE_URL MANIFEST EVIDENCE_DIR`。不要对真实项目运行写入验证。

## 遗留边界

没有更细映射的跨页片段无法精确拆成单页；未知来源片段仍未知。没有正文资源/有效哈希或整稿与资源不一致的坏登记，继续拒绝猜分段保存并保留原文件下载；本轮不通过重新OCR补齐。3个早期合成记录缺少文字资源，不能视为已有可编辑片段；详情在私有数据盘点中。Safari、Firefox、真实手机触控、系统级屏幕阅读器未验证。

回归发现并修复两项兼容问题：快速改变尺寸/面板时旧动画帧恢复覆盖新滚动位置，改为布局修改后同步恢复；导出完成但预览尚在排队时，打开的预览现在观察状态直至完成（仅读取状态，不新增生成/模型调用），关闭或切换后旧请求失效。

本阶段完成后停止，等待审核；不进入段落定位或疑点标亮阶段。

最终相关回归140项通过；单页原件预览专项另行21项通过，JavaScript语法与Python Ruff/编译检查通过。一次完整运行曾出现原件单页渲染返回FAILED，未复现稳定原因；保持原断言、增加返回值诊断后，专项及最终完整运行均通过。没有把该偶发失败宣称为已定位修复，首次失败记录保留在交付包。实际环境：Linux、Python3.12、LibreOffice7.4.7.2、中文Droid Sans Fallback字体、Chromium140.0.7339.16，CSP未绕过。

日常部署沿用`filetools-http-dev-review-r3`、`127.0.0.1:18971`和原数据根/配置/镜像。部署前无活动任务，备份38个项目元数据并记录4460个原件、正文、导出及已有文字/图片资源哈希。最终部署SHA及部署后保留核对记录由交付包报告给出。
