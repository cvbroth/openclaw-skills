# 独立HTTP单文件上传512MiB验证报告

> 后续PDF总页数已改为1000（含），见STANDALONE_PDF_1000_REPORT.md。本报告的200页记录是当时验证条件，历史证据不改写。512MiB与单任务5页保持。

基于R3提交b0846c79ea350559651937f46f1b1132b66c6fb2增量修改。实施说明STANDALONE_UPLOAD_512_PLAN.md。没有新OCR或云调用，不改生产、原件、已部署Skill及模板。

## 修改

示例配置与实际独立开发配置的service.upload_bytes改为536870912字节（512MiB）。现有配置校验原本已允许该上限，无需提高其他资源。PDF最大200页、单任务最多处理5页及像素/超时/内存限制原值保留。私有配置备份后仅修改上传参数，开发服务无活动任务时重启加载，其他配置逐项比对未变。

新增GET /api/limits只返回上传字节数、PDF页数及任务选页数，不暴露引擎配置或凭据。界面动态显示三项限制，前端超限提醒，后端返回413 UPLOAD_TOO_LARGE及limit_bytes。保持64KiB流式接收、磁盘额外512MiB保留空间、fsync与finally清理，不一次性read整个上传文件。仍要求单一Content-Length，不支持无限长chunked上传。

## 实际验证

scripts/test_upload_capacity.py在受限开发容器内开独立测试HTTP实例，使用相同Handler、文件校验与项目登记，enqueue替身禁止后续识别。32×32合法PNG附文件结束标记后的惰性尾部填充，恰好536870912字节，真实流式传输返回202，落盘字节与SHA一致；耗时2.615345秒，脚本服务端+客户端同进程峰值RSS61280KiB（约59.84MiB，含校验/哈希），没有512MiB整文件内存缓冲。仅字节容量证据，不代表512MiB真实扫描件性能。

536870913字节Content-Length在接收正文前返回413，不生成临时文件。断连不完整上传返回400，非法图片返回400；uploads目录均无遗留。临时测试项目与大文件结束自动清理，没有后台转换任务或模型调用。超限测试按实际+1字节边界，没有上传整份超限正文。额外单元测试验证六页选取违反5页任务上限、PDF超过配置页数仍拒绝，临时文件清理。

28项相关HTTP/评审回归测试通过20.16秒（5个已有PyMuPDF弃用警告），Ruff与diff检查通过。实际Chromium140页面显示512MiB、200页、5页三项，模拟超限File描述符触发前端拒绝且零上传请求；后端边界是上述真实HTTP验证。浏览器无JS错误。结果及合成截图见evidence/standalone-upload-512。
