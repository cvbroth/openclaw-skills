## 两条输出链与共享规则

- PDF：选定 Markdown → `content_structure.parse_markdown/reading_html` → `reading_style.emit_reading_assets` 的本地 CSS/字体 → 服务端 Playwright/Chromium 打印 → 逐页 PDF 合并。文字可搜索、复制；最终 PDF 不使用整页图片。
- Word：同一正文模型、样式快照和来源分组 → python-docx 可编辑 Word → LibreOffice 实际渲染用于检查和预览。PDF 原文直出不再依赖该 Word 转换。
- 两者共享标题、段落、粗斜体、列表、显式换行、正文顺序、阅读样式、字体补充、版本及来源映射。无试题结构猜测、选项自动组合、标题去重、正文改写。自定义模板保留原生成/分页链。
- 阅读样式1.0.0：A4、15mm边距、10.5pt主体、1.85倍行距、段落上下1em；标题比例及间距来自共同样式。浏览器缩放、窗口宽度及工具栏不属于文档样式。

新增 `deploy/Dockerfile.reading-pdf` 在现有服务镜像上固定 Playwright1.55.0及其 Chromium140.0.7339.16 headless shell 和系统依赖。每页先加载本地字体、等待 `document.fonts.ready`、再测量并打印，不请求外部资源。实际使用 API 参见 [Playwright PDF 文档](https://playwright.dev/python/docs/api/class-page#page-pdf) 与[浏览器依赖安装](https://playwright.dev/python/docs/browsers#install-system-dependencies)。

## 来源分页、预览与任务

同一来源页所有片段按登记顺序合并；来源页之间独立生成，下一页不回填上一页。映射缺失、跨页歧义、顺序回退、空正文和未支持格式均列出页码及原因。默认不跳页，也不把失败页变成成功空白页。

默认按阅读样式检查。仅明确启用紧凑适配后，先减间距，再按0.5pt步长调整字号，始终遵守用户可见的最小字号/行距/段距。DOM 高度、实际 PDF 页数、文本完整性、字形及文字边界共同校验；仍溢出就失败，不裁切、不隐藏溢出、不放开续页。

导出窗口增加按来源物理页输入的 **PDF纸张预览**，采用最终 PDF 相同 HTML/CSS、字体、测量及打印路径；预览图片只是候选真实 PDF 的显示形式。展示纸张、边距、实际参数、字体状态及溢出页数；修改参数自动刷新。完整范围检查展示全部阻塞页、逐页进度，检查快照可再次打开。Word 使用明确标注的“Word实际预览”。保持单顶栏、双栏正文、按需辅助面板。

单页浏览器操作60秒、打印30秒；Word单页60秒、最终长文档按页数增加超时，整任务按片段数量分配最多24小时，不沿用整册40秒限制。浏览器每次仅持有一个页面/context，每25次重启；逐页更新进度，取消仅终止本任务拥有的进程，其他预览不受影响。发布要求所有请求的文件实际存在，失败不得假成功。历史导出不覆盖。

快照保存正文版本与哈希、样式及字体哈希、显式范围与未包含页、每页尝试参数和实际映射、浏览器版本/算法及 HTML/CSS 哈希。技术报告、评论、质量评价不写入正文。

## 限制

严格阅读样式对密集习题页常溢出，需要用户明确选择紧凑边界。表格、图片、引用/分隔线、代码/HTML块、高级标题及不支持内联格式暂阻塞并说明，不静默丢失。第145页需要已有有效修订或补充正文；本轮不补写。第7、168页需用户另定可接受的参数边界，本轮没有暗降字号。未测试Microsoft Word桌面字体替换效果，未进行整册Word导出。本轮不扩展模板导入、段落坐标或OCR。
