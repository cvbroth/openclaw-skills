# V1.2.1 普通用户说明

只有附件时，Agent 确认登记状态后等你说明任务；附件带问题时，登记中会告诉你仍在处理，不要因为 pending 就重复上传。后台结束后在下次聊天或你说“查看登记结果”时可查，没有主动回复保证。错误会给恢复方式，不把空识别当成功。

## 登记整理当前工作区

可以说“把我工作区里的业务文件登记整理一下”。Agent 查看自己当前工作区，排除配置、记忆、Skill、项目源码/依赖、凭据、隐藏系统文件和filetools目录，分批登记其余业务资料。报告原位置、分类、file_id、成功/重复/跳过/失败和进度；相同内容快照去重。很多历史文件不会全部选入当前处理会话，真正要处理哪个再选择。

默认是“分类快照整理”：保存独立快照和目录记录，原目录、文件名、原件不动，不自动全文提取、入库或建立向量索引。若要“移动原件整理”，要另行明确说，先核对具体移动清单、重名和引用影响；当前 FileTools 没有通用原件移动工具，可靠的现有能力不足时会保留原件并报告限制。

## 用个人 Samba 上传大文件

继续用你已有的个人共享 chen / liang / azl，遵循实际配置的上传完成约定。当前 Chen 可直接上传到 Incoming，等客户端确认上传完成并关闭文件后，再通知 Agent 文件名及任务；使用 Uploading → Incoming 的其他环境仍先关闭文件再移动。网络中断时不要提前通知，大小暂时不变不代表上传结束。Agent 不会自动扫描或处理 Incoming。

管理员需先配置个人 Incoming 只读来源和实际读取权限。Agent不会自动找到所有NAS/Family文件。你可以要求 snapshot（独立版本，占空间）或 reference（原件留NAS，使用时校验版本）；更新原件后需要登记新版本。处理结果写自己的filetools，原件不会被改写或搬走。

## 录音转写与整理

说“只给我原始转写”时，Agent 按你指定范围交付带时间戳的原稿，不自动生成纪要。说“整理成纪要并列出疑点”才生成独立临时整理稿；整理来自大模型，不能当作识别原话或准确性保证。听不清、姓名、数字等疑点附原片段和时间范围，你听原音后可说“00:42–00:48 的姓名确认为陆某，请更新整理稿”。Agent 在新稿中记录确认内容，保留其他未确认疑点，原转写及旧稿不覆盖。

整理、发送和确认更正都不会自动永久保存或导入知识库。需长期保留时明确说“保存原始转写”或“保存这份更新后的整理稿”；现有保存工具会标记所选稿，但保留整个任务产物包，包括原转写和其他整理稿。若只允许永久保留一份稿且禁止附带其他稿，当前接口无法满足，Agent 应报告限制。临时整理稿仍按缓存策略清理。当前没有专门的试听或人工复核界面，也不保证中文转写正确。

## 打开保存结果

说“保存这次结果”后，结果成为独立 saved 版本，临时缓存不会自动出现在共享。管理员启用后：chen用 Chen-Results，liang用 Liang-Results，azl用 AZL-Results；main 与chen仍是不同工作区。

- Windows：资源管理器连接既有服务器，例如 `\\NAS\Chen-Results`，使用你已有的个人账号，下载到本地后编辑。
- macOS：访达“前往→连接服务器”，例如 `smb://NAS/Chen-Results`，使用已有账号。
- iPhone：文件App“连接服务器”，输入现有服务器地址、个人账号，再打开对应结果共享。

示例 NAS 是你真实可达服务器的占位名。远程继续沿用已有客户端/樱花隧道及认证，不承诺三个系统都支持相同端口写法。首次连接失败先核对既有客户端与网络，再由管理员检查共享/权限；不要公开密码。

通过 Samba 访问结果共享时只读，不能上传、覆盖、删除、重命名或直接编辑NAS结果。Samba 账号与保存区所有者 UID 相同时也能开启共享：Samba 访问只读，服务器本地所有者仍可写。不会为此降低 FileTools 服务的本地写入权限。原上传仍在个人共享；可下载结果副本编辑。保存目录为分类/版本编号，含产物、来源记录JSON和必要图片，不是只有一个展平Word文件。正文引用图片需一起下载同一版本目录；文件名按产物manifest为准，不固定为content.md。原音频逐字稿和派生纪要分开，OCR/公式/复杂表格的质量限制仍见V1.2说明。

本文原版本的本地测试不代表所有生产环境验收。2026-10-05 用户补充的 Chen 生产 PDF/录音流程验证及其边界见 [交接增量](../HANDOFF.md#9-服务器接手增量2026-10-05)；其他账号、客户端及远程连接仍须分别验收。
