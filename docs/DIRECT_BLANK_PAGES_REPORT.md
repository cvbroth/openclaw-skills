# Markdown 原文直出：缺页、范围与基本格式修复

起始提交：`3b72f2322e0bc400026be843739d1143ba97b013`。执行时再次 fetch，远端仍为此提交。日常开发分支起始干净；外围工作区已有修改保留，使用独立工作树实施。适用约定：根目录 `AGENTS.md`。本轮没有重新 OCR、调用付费模型、修改模板导入或改动无关服务。

## 实现

- 默认仍阻止缺失正文。导出窗口先显示本次实际来源范围、预计页数、所有缺页及原因，用户明确勾选“缺失正文页保留为空白页”后才允许占位。
- 未登记来源页、整页所有片段均无正文可以占位。同页存在有效文字但另一片段缺失属于部分正文，不可整页替换。映射不明、完整性/资源错误、未支持格式和溢出始终阻塞。
- 每张占位页真正占一张 Word/PDF 页，正文完全空白。登记 `PLACEHOLDER`、来源页、实际输出页及原因；项目结果摘要和导出历史展示原因。没有改写 Markdown、历史提取错误或成功状态。
- 已知来源映射按所选范围检查；范围外145页不再阻止6–60页。全量资源组装校验保留，资源损坏不会被占位开关隐藏。来源关系无法确定时继续阻塞，不从片段序号猜页码。
- 区分导出范围与纸张预览页，新增“仅导出当前预览页”。版本、范围、格式、适配参数变化立即清空旧结果/错误；修订序号校验所有异步响应，并取消自身旧任务。排队任务可立即取消，出队不再执行；不取消其他任务。
- 生成之前必须完成与当前参数完全一致的所选格式检查。快照保存文字版本、哈希、样式1.1.0、占位策略、原因、来源/输出页映射、字体与渲染器信息；旧导出文件保持不变。

## 阅读和导出格式

共同使用 `content_structure.parse_markdown` 和 `reading_style`。引用保留段落、层级缩进和左边线；H4–6保留真实级别并映射 Word 标题样式；分隔线保留原始标记字符，同时绘制细线；代码/HTML代码作为转义后的文字展示，保留空格和换行，不执行。标题、粗体、斜体、列表及普通竖线沿用已有支持。

阅读器受控 HTML 白名单已增加 H4–6 和三种生成的格式类，仍剥离任意事件和属性。旧资源无格式化 HTML 或已有旧缓存时使用共同解析生成的 fallback，无需改写原文。

PDF：共同解析 → 阅读 HTML/CSS/本地字体 → 服务端 Chromium 打印；Word：共同解析/样式 → 可编辑 DOCX → LibreOffice 实际分页验证。各自检查完整文字、字体、边界和来源单页约束。Word 段距、代码背景内边距及字体度量与浏览器存在细微差别，故独立检查，不承诺像素一致。真实表格、图片等尚不支持的直出格式继续明确阻塞；没有以空白页绕过。
