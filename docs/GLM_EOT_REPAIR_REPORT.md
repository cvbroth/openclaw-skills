## 真实结果与原因边界

运行日志现在同时注册59246和59253为EOG，确认补丁被引擎加载。但小样没有返回期望正文或自然终态；反复输出任务标签，主动中止时已观察到“Page Text Recognition:”319次、7337个可见字符，保存全部原始流。未用部分内容或人为截断冒充成功。受控SIGINT停止，容器exit1、OOMKilled=false；原生终态缺失。

最后资源采样时106.128秒，cgroup CPU204.051核秒（约1.923核）、memory.peak5,070,458,880字节（约4.72GiB），swap/OOM0。容器实际存续107.755秒；这不是成功识别速度。最终清理发生观察器 `KeyboardInterrupt` 后未初始化 `inference_seconds` 的错误，因此没有原生receipt/final-resources，使用明确标识的manual-abort和最后采样，不补造终态。已修复控制器初始化/中断清理并添加合成回归；修复后不重跑模型，本轮小样原记录保持。

**已验证：** EOT缺项已补入并实际注册，原张量不变，当前导入组合仍无法通过小图自然结束。

**未验证：** 上轮具体重复token序列、完整根因、补丁对原分发完整调用路径的因果效果、正式两页质量和耗时。没有捕获实际生成token ID，不把可见任务标签重复等同于59253反复生成；也不以本次失败证明EOT与上轮异常无关。上轮注册缺项是事实，本次上游建议的元数据＋本地导入操作未跑通；因导入还改变了renderer/parser，本轮未完成严格的EOT因果验证，不能据此断言EOT修复本身无效。按小样失败的停止要求保留这一限制，不继续修改导入配置重试。

本轮到此停止GLM，不尝试第二方案或其他引擎。后续M3独立实验不被此失败阻断。
